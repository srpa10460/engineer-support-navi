# エンジニアサポートNavi

Built with Claude: Japan 2026 提出用アプリ（技術検証版）

医療機器の障害対応に当たるサービスエンジニアを支える、案件整理と提案の下書きのためのデモアプリです。使うデータは、すべて架空です。実在の病院、装置、顧客、個人のデータは含みません。

このアプリは、診断、治療、医療判断を行いません。装置の復旧に関する技術情報の整理と、施設への説明文の下書きだけを扱います。

## 目的と対象

- 対象ユーザー: 新人、若手のサービスエンジニア。デモの利用者の区分は junior_fse の 1 種類です（自己申告のラベルで、認証ではありません）。
- 解決する課題: 緊急の障害連絡を受けた現場のエンジニアが、症状の記録、装置の特定、資料の根拠の確認、安全面の確認、施設への説明までを、1 人で抱え込みがちなこと。
- 流れ: 画面は 5 つの工程タブです。1 症状記録、2 装置特定、3 資料検索、4 安全確認、5 提案。

## Claude の役割と、人の判断責任

- Claude の役割は、提案の下書きを作ることだけです。入力は、保存済みの案件の項目、確定した装置、根拠資料の抜粋、安全確認の結果です。
- 事実の確定、装置の確定、承認、施設への連絡、復旧の時刻や代わりの運用の決定は、Claude は行いません。
  - 装置の確定は、候補から人が明示的に選んだときだけです。
  - 提案の承認は、エンジニアが画面上で行います。承認の内容はサーバーに保存せず、施設への送信も行いません。
  - 復旧の時刻は確約せず、運用は施設が判断する、という書き方に限ります。
- エンジニアは、下書きを直せます。直した文章は、同じ決定的なチェック（医療表現、判断表現、安全ゲート）を通ったときだけ承認できます。

## 実装済みの機能

- 案件の登録と取得（症状、エラー番号、受付番号。保存前に個人情報の形式を検査）
- 装置の検索と確定（架空の装置 4 台。自動では確定しない）
- 技術資料の検索と、根拠の参照（架空の資料 4 件。版とセクションを付けて返す）
- 安全ゲート（決定論的なルール判定。危険な操作、個人情報、不正な入力を拒否）
- 提案の下書き（Claude）
  - 根拠チェック: 渡した根拠資料にない引用や、根拠のない確認候補を検出して表示し、承認を止める。
  - 医療表現と判断表現の抑止: 下書きに、診断、治療、患者への言及、運用や検査の可否の決定が含まれたら、表示せずに止める。
  - 下書きの文章も、安全ゲートに通す。
  - 出力の上限に達した場合は、部分的な下書きを出さず、失敗として表示する。
- 画面（5 つの工程タブと台帳の表示）

## 未実装

- 引継ぎ、障害復旧の支援、秘密情報のスキャナ
- データベース（保存は JSON ファイル）、認証、複数の利用者
- 施設への送信、外部システムとの連携
- 公開環境への配備（localhost での実行を前提にしています）
- デモ動画の終盤で述べる将来構想の機能
- 部品の手配は実行しません。提案の下書きに「部品手配の準備（候補）」として書くだけです。

## 動作環境

- Node.js 20.9 以上、npm（確認した環境: Node.js v22.23.4）
- Claude の呼び出し（提案の下書き）は、macOS 専用です。API キーを macOS のキーチェーンから読むためです。
  - そのほかの機能（案件、装置、資料、安全ゲート）は、キーなしで動きます。
  - キーがない場合、提案の下書きは失敗として表示されます（作り物の下書きは出しません）。

## 実行方法

```bash
cd app
npm install
npm run dev -- -H 127.0.0.1
```

- 画面: http://127.0.0.1:3000
- 生存確認: http://127.0.0.1:3000/api/v1/health
- 同じネットワークの他の端末から呼ばれないよう、`-H 127.0.0.1` を付けてください。付けないと、開発サーバーは LAN でも待ち受けます。提案の呼び出しは課金を伴います。

### 環境設定

- 環境変数は、`.env.example` を参照してください。必要なときだけ `.env.local`（Git 除外）に書きます。いずれも未設定で動きます。
  - `ESN_CLAUDE_MODEL`: 使う Claude のモデル。未設定なら claude-sonnet-5-5。
  - `ESN_DATA_DIR`: 案件、拒否記録、呼び出し記録の保存先。未設定なら `../runtime/data`（app の 1 つ上）。絶対パスで指定してください。相対パスは、サーバーを起動したときの作業ディレクトリが基準になります（未設定時の既定の保存先とは、基準が異なります）。空文字は指定しないでください（`.env.example` を参照）。
  - `ESN_PROPOSAL_FIXTURE`: 固定応答の名前（動作確認とテスト用）。「審査員向けの操作手順」の経路 A を参照。
- API キーは、環境変数にもファイルにも置きません。実行時に、macOS のキーチェーンのサービス名 `anthropic-esn` から読みます。登録は、ターミナルで次を実行し、プロンプトにキーを貼り付けます（コマンドラインにキーを書かない）。

```bash
security add-generic-password -s anthropic-esn -a "$USER" -w
```

## 審査員向けの操作手順

画面の操作を、架空の入力例で順に試せます。画面の URL（http://127.0.0.1:3000）は、お使いのパソコンの中だけで開く URL で、公開された URL ではありません。

### 経路 A: 操作の確認（キー不要。固定応答）

実際の Claude は呼びません。キーチェーンのキーも読みません。課金もありません。提案の下書きは、あらかじめ用意した固定の文章で、実際の Claude の生成結果ではありません（画面に「テスト用の固定応答（実際の Claude ではありません）」のバッジが出ます）。

```bash
cd app
npm install
ESN_PROPOSAL_FIXTURE=ok npm run dev -- -H 127.0.0.1
```

- `ESN_PROPOSAL_FIXTURE` に空でない名前を設定している間は、実際の Claude へは切り替わりません。バッジが出ないときは、固定応答ではない、ということです。
- 開発サーバー（`next dev`）は、Next.js の更新確認のために、registry.npmjs.org へ問い合わせることがあります（アプリのデータは含みません。外部への通信を遮断した検証環境で、この問い合わせを 1 件確認しました。内容は推定です）。

操作の順序と入力例（すべて架空）:

| 工程 | 操作 | 期待される表示 |
|---|---|---|
| 1 症状記録 | 「症状の入力例を入れる」を押す（症状欄に「E210 が表示され Ready にならない」が入る。登録は自動では行いません）。「登録」を押す | 「登録完了」 |
| 2 装置特定 | 機種の選択肢から「HeliosXR-A1（2 台）」を選び、「候補を検索」を押す。候補（HVN-DEV-XR-001 など 2 台）から 1 台を自分で選び、「この装置で確定」を押す | 「装置を確定しました」 |
| 3 資料検索 | 「資料を検索」を押す | 根拠資料に、節 SEC-E210 と SEC-E210-CHK が版つきで出る |
| 4 安全確認 | 「例: 危険な依頼」を押して「確認」を押す。次に「例: 個人情報の保存依頼」、「例: 通常の相談」でも試す | 前の 2 つは「拒否しました」（規則 ID と相談先）、「通常の相談」は「許可しました」 |
| 5 提案 | 「下書きを作る」を押す。下書きの欄を編集し、画面上で承認する | 固定応答のバッジ、編集の印、承認 |

- 画面を下へスクロールすると、右下に「▲ 上へ」が出ます。押すと、ページの先頭に戻り、工程タブを押せます。
- 工程 4 の拒否は、提案を止めません。拒否のあとも、同じ案件で、工程 5 に進めます。
- 承認は、画面上の確定だけです。施設への送信は行いません。
- 同じ受付番号は、再登録できません。もう一度試すときは、受付番号を別の番号に変えてください。
- 機種の選択肢は、登録した案件の設置先にある機種です。設置先 HVN-SITE-001 は HeliosXR-A1（2 台）と HeliosRF-B2（1 台）、HVN-SITE-002 は HeliosXR-A1（1 台）です。
- 資料があるエラー番号は、E210 と E440 で、どちらも HeliosXR-A1 の資料だけです。ほかの機種（例: HeliosRF-B2）や、ほかのエラー番号では、資料検索は成功しますが資料は 0 件で、提案は「HTTP 409 no_evidence」で止まります。操作の確認では、E210 と HeliosXR-A1 を使ってください。

### 経路 B: 実際の Claude の API で下書きを作る

- 準備: 上の「環境設定」のとおり、macOS のキーチェーンに API キーを登録します。起動は `npm run dev -- -H 127.0.0.1` です（`ESN_PROPOSAL_FIXTURE` は設定しません）。
- 送られる内容は「外部への送信」、記録は「ローカルに残る記録」を参照してください。提案の呼び出しには利用料金がかかります。
- 生成される文章は、呼び出しごとに異なります。出力は、根拠資料との整合と安全上の検査を通ったものだけが、下書きとして表示されます。検査は完全ではありません。

## 外部への送信

- 送信先は api.anthropic.com だけです。送るのは提案の下書きを作るときだけで、1 回の呼び出しに、次の項目を含めます。
  - 受付番号、設置先の ID、症状（保存済みの文章）、エラー番号
  - 確定した装置の情報（装置 ID、機種、部屋、設置年）
  - 根拠資料の抜粋（資料 ID、版、セクション、セクションの見出し（title）、本文の抜粋）
  - 安全ゲートの結果（許可か拒否かと、規則 ID のみ）
- 安全確認の欄に入力した文章は、送りません。
- 案件の症状は、保存前に個人情報の形式検査（SG-DATA-01）を通ったものだけが保存され、送信の対象になります。この検査は形式によるもので、完全ではありません（下の「安全上の制約」を参照）。
- ローカルに残る記録は、次の節「ローカルに残る記録」を参照してください。

## ローカルに残る記録

保存先は、`ESN_DATA_DIR`、未設定なら `../runtime/data`（app の 1 つ上）です。次のファイルが作られます。

| ファイル | 内容 |
|---|---|
| `cases.json` | 登録した案件（症状、エラー番号、受付番号、装置の確定など） |
| `audit_rejections.jsonl` | 安全ゲートの拒否 1 件につき 1 行。経路、規則 ID、原因の区分、入力の長さ、切り詰めの有無のみ。拒否した本文は残しません |
| `proposal_calls.jsonl` | 提案の呼び出し 1 回につき 1 行。時刻、案件 ID、結果、要求 ID、応答 ID、モデル、トークン数、所要時間。プロンプト全文とキーは残しません |

`proposal_calls.jsonl` には、次の 2 つの場合だけ、Claude の出力の一部が残ります。

| 場合 | 結果の値 | 保存される範囲 |
|---|---|---|
| 出力の形式が不正で、下書きとして読めない | `invalid_output:…` | 出力の長さ、先頭 300 字（`raw_head`）、末尾 200 字（`raw_tail`） |
| 下書きの文章が安全ゲートに拒否された | `blocked:SG-…`（規則 ID） | 下書きの文章（各項目をつないだもの）の先頭 2,500 字（`prose`） |

- 上記以外の結果（成功、根拠不明、医療表現や判断表現による停止、呼び出しの失敗、出力の打ち切り、固定応答の失敗）でも、行は作られますが、出力の抜粋は含まれません。
- 次の場合は、`proposal_calls.jsonl` に行そのものが作られません。
  - 呼び出しの上限を超えた（HTTP 429）。この場合は、カウントも増えません。
  - リクエストの本文が不正、または大きすぎる（HTTP 400、413）。
  - 案件がない（404）、装置が未確定（409）、装置が台帳にない（409）、根拠資料が見つからない（409）。
  - 確認モード（エンジニアが直した文章のチェック。Claude を呼ばない）。常に行を作りません。
  - 固定応答の名前が不明（HTTP 500）。
  - 記録の書き込み自体に失敗したとき（処理は止まらず、記録は残りません）。
- 残るのは Claude の出力です。ただし、出力には、入力に由来する情報（症状の文、エラー番号、受付番号、装置の情報など）が含まれ得ます。個人情報の検出をすり抜けた情報があれば、それも含まれ得ます。
- これらのファイルは自動では削除されず、上限もありません。追記され続けます。ログの回転や期限切れの処理は、実装していません。
- 上の 3 つのファイルは、名前（`cases.json`、および `.jsonl` で終わる名前）が、リポジトリのルートの `.gitignore` に当たるため、除外されます。既定の保存先（リポジトリのルート直下の `runtime/`）は、フォルダごと除外されます。
- ただし、下の手順で作る `.bak` と `.new` は、名前が除外に当たりません。保存先が `runtime/` の外（`app/` の中や、`ESN_DATA_DIR` でリポジトリ内に指定したフォルダ）だと、そのままコミットされ得ます。写しは、リポジトリの外に置いてください。共有、バックアップ、提出の前に、保存先を確認してください。

### 記録の確認と削除

このアプリは、記録を削除する機能を持ちません。手順は、すべて手作業です。先にサーバーを止めてください。実際の記録を変える前に、必ずバックアップを取ります。

重要:
- バックアップには、消したいはずの出力の抜粋が、そのまま残ります。バックアップは、抜粋を含む記録と同じ扱いにしてください。
- バックアップの名前には、実行した日時が入ります。以前に作った `.bak` があっても、今回のバックアップとは別のファイルです。手順の最後に表示される、今回のバックアップのパスだけを、今回のものとして扱ってください。
- 同じ名前のバックアップが既にある場合、または `.new` が既にある場合は、何もせずに中止します。
- `.bak` と `.new` は、名前が `.gitignore` の除外に当たりません。バックアップは、リポジトリの外のフォルダに置いてください。
- 記録の中に、JSON として読めない行（壊れた行）があるときは、処理を中止します。元のファイルは変更しません。中止のメッセージが出たら、以降の手順は行わず、原因を確認してください。
- 壊れた行で中止した場合でも、その前に作ったバックアップは、そのまま残ります（元のファイルと一致を確認済みのもの）。
- 行の区切りは、改行（U+000A）だけです。記録の中の文章に、U+2028 や U+2029 などの文字が含まれていても、1 行として扱います。

```bash
cd "<保存先>"                       # ESN_DATA_DIR、または既定の runtime/data
f=proposal_calls.jsonl
bkdir="<リポジトリの外のバックアップ用フォルダ>"
bk="$bkdir/$f.$(date +%Y%m%d_%H%M%S).bak"      # 実行のたびに名前が変わる

# 1. 何があるかを確認する（中身は表示しない）
ls -l

# 2. バックアップの作成、抜粋の一覧、抜粋を除いた写し（"$f.new"）の作成。
#    元の "$f" は変更しない。途中で失敗したら、そこで中止する（括弧の中で実行する）。
(
set -eu
[ ! -e "$f.new" ] || { echo "$f.new が既にあります。中止します"; exit 1; }
[ ! -e "$bk" ]    || { echo "$bk が既にあります。中止します"; exit 1; }
mkdir -p "$bkdir"
cp "$f" "$bk"
cmp "$f" "$bk"
echo "今回のバックアップ: $bk"
python3 - "$f" <<'PYEOF'
import sys, json, os
src = sys.argv[1]
dst = src + ".new"
if os.path.exists(dst):
    sys.exit(dst + " が既にあります。中止します")
rows = []
with open(src, encoding="utf-8", newline="\n") as fh:   # 改行（U+000A）だけで行を分ける
    for n, line in enumerate(fh, 1):
        line = line.rstrip("\n")
        if line.strip() == "":
            continue
        try:
            rows.append((line, json.loads(line)))
        except Exception:
            sys.exit(f"{n} 行目が JSON として読めません。中止します（元のファイルは変更していません）")
keys = ("raw_head", "raw_tail", "prose")
for line, j in rows:
    if any(k in j for k in keys):
        print(j.get("at"), j.get("case_id"), j.get("outcome"), [k for k in keys if k in j])
kept = [line for line, j in rows if not any(k in j for k in keys)]
with open(dst, "x", encoding="utf-8", newline="\n") as out:
    for line in kept:
        out.write(line + "\n")
print(f"全 {len(rows)} 行を確認。抜粋を除いた {len(kept)} 行を {dst} に書きました")
PYEOF
)

# 3. 行数を比べ、"$f.new" の内容を確認する
wc -l "$f" "$f.new"
```

確認ができたら、次のように、1 つずつ、ファイル名を指定して行います（ワイルドカードは使いません）。

```bash
# 写しで置き換える（元の "$f" は、手順 2 で表示された今回のバックアップに残っている）
mv "$f.new" "$f"

# 今回のバックアップが不要になったときだけ、そのパスを 1 つ指定して、確認しながら削除する
rm -i "$bk"
```

- `rm -i "$bk"` は、手順 2 を実行したのと同じシェルでだけ、今回のバックアップを指します。別のシェルでは、手順 2 で表示されたパスを、そのまま指定してください。以前に作った `.bak` を消す手順ではありません。
- 案件データ（`cases.json`）や監査記録（`audit_rejections.jsonl`）には、部分的に消す機能も手順もありません。消すときは、対象のファイルを、名前を指定して自分で確認しながら削除します。
- 手順の 2 は、作り物の記録で動作を確かめています。確かめた場合は、正常、壊れた行、`.new` が既にある、同じ名前のバックアップが既にある、以前の `.bak` が残っている、U+2028・U+2029 などを含む行です。実際の記録には使っていません。

## 安全上の制約

- 技術検証版で、架空データのみを扱います。実データを入れないでください。
- 個人情報の検出は、形式（電話番号、メールアドレス、氏名らしい並びなど）による判定です。すべての個人情報、すべての危険な入力を防ぐ保証ではありません。検出できなかった情報は、案件に保存され、提案の下書きの呼び出しで Claude に送られ得ます。
- デモ動画の章見出しと補足は、次の文言です。実装との関係を、あわせて示します。
  - 主見出し「危険な依頼を止め」「大切な情報を守る設計」（2 行）、補足「危険な依頼や個人情報の保存要求を、規則に基づいて拒否します。検出はルールと形式による判定で、完全ではありません。」、3 つの箱「危険な操作の依頼を拒否」「個人情報の保存依頼を拒否」「相談先を表示」。補足の 1 文目は、続く場面 6 でも、見出しの下に表示します。
  - これは、規則による拒否の説明です。すべての情報の外部への送信を防げる、という保証ではありません。
  - 実装が行うのは、次のことです。個人情報の形式検査（SG-DATA-01）を、案件を保存する前に行い、検出したら保存しません（HTTP 403）。保存されなかった情報は、提案の下書きの呼び出しで Claude に送る対象になりません。安全確認の欄に入力した文章は、保存も、Claude への送信もしません（検査して、結果の規則 ID だけを返します）。
  - 実装が行わないのは、次のことです。Claude へ送る直前の内容に対する、個人情報の検査（送信の遮断）は、ありません。検出できなかった情報は、案件に保存され、提案の下書きの呼び出しで Claude に送られ得ます。案件のデータと根拠資料の抜粋は、提案の下書きを作るときに、実際に api.anthropic.com へ送られます。
- 既存の安全ゲートは、AI の出力に含まれる専門語（例: 「インターロック」の語、線量や電圧を表す語）を危険な操作の記述と誤検知して、下書きを止めることがありました。そのため、提案のプロンプトで、これらの語を避けて言い換えさせています。ゲートの規則自体は変えていません。
- 呼び出しの上限があります（1 プロセスあたり 40 回、1 案件あたり 6 回。メモリ上のカウンタで、サーバーを再起動すると戻ります）。超過すると HTTP 429 を返し、`proposal_calls.jsonl` には行を作りません（「ローカルに残る記録」を参照）。
- 出力の上限は 3,500 トークンです。上限に達した出力は、失敗として扱います。
- Claude の出力は、実行ごとに変わります。同じ入力でも、同じ下書きにはなりません。
- `src/proposal/fixtures.ts` は、動作確認とテスト用の固定応答です。環境変数 `ESN_PROPOSAL_FIXTURE` を設定したときだけ使われ、使われている間、画面に「テスト用の固定応答（実際の Claude ではありません）」のバッジが出ます。設定しない通常の実行では使いません。

## テスト

提出物に含まれるのは、架空データを使った自動テストの 13 本です。いずれも Claude を呼びません（課金は発生しません）。

```bash
# 毎回、新しい一時ディレクトリを、サーバーとテストの両方に指定する
export ESN_DATA_DIR=$(mktemp -d)
npm run build
npx next start -H 127.0.0.1 -p 3299 &        # 別のターミナルでもよい
export ESN_BASE_URL=http://127.0.0.1:3299     # /api/v1 は付けない

npm run test:health
npm run test:tp01
npm run test:tp02
npm run test:tp03
npm run test:tp04
npm run test:tp04r
npm run test:tp04r2
npm run test:tp04r3
npm run test:tp04r4
npm run test:invariant
npm run test:boundary
npm run test:tp04r5
npm run test:concurrency
npm run lint
```

- テストの入力には、検出器を試すための架空の氏名、電話番号、メールアドレス（example.com などの予約済みドメイン）が含まれます。実在する個人情報ではありません。
- 提案機能の検証の範囲:
  - 提出物に含まれる 13 本が確認するのは、提案以外の部分です（health、案件、装置、資料、安全ゲート、記録の整合、境界、同時実行）。提案の API と画面（Claude の呼び出し、根拠チェック、承認）は、1 本も含まれていません。上の 13 本が PASS しても、提案機能の検証にはなりません。
  - 提案の API のテストと画面のテストは別にあり、この提出物には含まれません。どちらにも、固定応答を使わない最後の場面があり、キーチェーンにキーが登録されていれば、実際の Claude を呼び出します（課金を伴います）。キーがなければ、呼び出しは失敗として扱われます。どちらのテストも、固定応答の場面以外では、呼び出しを止める仕組みを持ちません。
  - 実際の Claude を呼び出す確認用のスクリプトも別にあります（テストではありません）。
  - 別の環境でのテスト結果は、記録ファイルが残っていますが、提出物のコードでの結果ではありません。画面のコードが記録の後に変更されているため、提出物の最終のコードに対する結果は、未確認（UNKNOWN）です。
  - 提案の呼び出しは課金を伴うため、提出物の 13 本では実行していません。
  - `npm run lint` は、警告が 1 件出ます（`src/app/api/v1/cases/[id]/proposal/route.ts` の `MAX_BODY_BYTES` が未使用。動作への影響なし）。
  - ソースのコメントに、開発時の準備資料への参照が残っています。その資料は、この提出物には含まれません。
  - 独立した監査の結果は、この README の範囲外です。

## 構成

- `src/app/` 画面と API ルート（`api/v1/…`）
- `src/lib/` 案件の保存、装置検索、資料検索、安全ゲート（`safetyGate.ts`）、監査記録
- `src/proposal/` 提案の下書き（`claude.ts` 呼び出し、`prompt.ts` 指示、`validate.ts` 検査、`log.ts` 記録、`fixtures.ts` 動作確認とテスト用の固定応答）
- `src/data/` 架空の装置と資料
- `scripts/` 自動テスト
