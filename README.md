# エンジニアサポートNavi

Built with Claude: Japan 2026 提出用リポジトリ（技術検証版）

医療機器の障害対応に当たるサービスエンジニアを支える、案件整理と提案の下書きのためのデモアプリです。使うデータはすべて架空です。診断、治療、医療判断は行いません。

起動の最短手順は、次のとおりです（詳細と注意は [実行方法](app/README.md#実行方法) を参照）。

```bash
cd app
npm install
npm run dev -- -H 127.0.0.1
```

画面は http://127.0.0.1:3000 で開きます。`-H 127.0.0.1` は、同じネットワークの他の端末から呼ばれないための指定です。この URL は、お使いのパソコンの中だけで開く URL で、公開された URL ではありません。

キーなしで画面の操作を確認するには、`ESN_PROPOSAL_FIXTURE=ok npm run dev -- -H 127.0.0.1` で起動します（提案の下書きは固定の文章で、実際の Claude の生成結果ではありません）。入力例と操作の順序は、[審査員向けの操作手順](app/README.md#審査員向けの操作手順) を参照してください。

## 画面の流れ

緊急の障害連絡を受けたエンジニアが、5 つの工程タブを順に進めます。

1. 症状記録: 症状、エラー番号、受付番号を登録します。保存の前に、個人情報の形式検査を行います。
2. 装置特定: 装置の候補を検索し、エンジニアが 1 台を選んで確定します。自動では確定しません。
3. 資料検索: 確定した装置とエラー番号に対応する技術資料を、版とセクションつきで確認します。
4. 安全確認: 相談する文章が安全か、ルールで確認します。規則に該当する危険な操作の依頼や個人情報の保存依頼を、拒否します。
5. 提案: Claudeが施設向けの説明と提案の下書きを作り、エンジニアが編集して画面上で承認します。出力には根拠資料との整合や安全上の検査を行いますが、検出は完全ではありません。

## Claude の役割と人の判断責任

- Claude の役割は、提案の下書きを作ることだけです。
- 事実の確定、装置の確定、承認、施設への連絡、復旧の時刻や代わりの運用の決定は、Claude は行いません。判断するのはエンジニア、決めるのは施設です。
- 承認は画面上の確定だけです。施設への送信は行いません。

## 制約

- 技術検証版で、架空データのみを扱います。実データは入れないでください。
- 認証や利用者ごとのデータ分離、施設への自動送信、外部業務システムとの連携は実装していません。
- 案件などはローカルの JSON ファイルに保存します。保存先、残る記録の内容、確認と削除の方法は、[app/README.md](app/README.md) を参照してください。
- 提案の下書きは Claude を呼び出します。macOS のキーチェーンのキーが必要で、課金を伴います。それ以外の機能は、キーなしで動きます。
- 個人情報や危険な入力の検出は、ルールと形式による判定で、すべてを防ぐ保証ではありません。
